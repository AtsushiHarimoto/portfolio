# 11.2 小說創作 Skill 架構設計：從大綱到 ASMR 雙軌輸出
> **類型**: 系統架構設計 > **日期**: 2026-03-26 > **來源**: 內部核心技術庫

---

## 摘要

本文檔規範了一套專為 Claude Code 設計的「AI 輔助網路小說創作 Skill」。此 Skill 將引導 AI 與人類使用者互相協作，實現從零開始的故事規劃（World-building）、自動章節拆解，直到最終產出高質量的正文內容。

我們特別引入了「雙軌輸出機制」，在產出傳統網文的同時，系統將自動同步生成帶有停頓標記與環境音效的「ASMR 口播腳本版」，以搶佔越來越龐大的有聲書與聽書市場。此架構大幅降低了創作者跨媒材轉換的負擔。

> [!NOTE] 
> 💡 **白話文解釋**
> 整個 Skill 系統就像一個劇組的「全能大導演」。
> 第一階段，導演找編劇開會（7步問答），確定世界觀和角色。
> 第二階段，導演把劇本拆成一場場戲，發給場記（章節 Prompt）。
> 第三階段正式開拍時，導演不只指導演員怎麼演（傳統網文），還同時拿著大聲公告訴收音師哪裡要喘息、哪裡要加腳步聲（ASMR 腳本）。一次拍攝，兩種享受。

## 背景

過去的 AI 寫作工具多半缺乏「長期記憶」與「執行約束」，寫到後期容易崩壞（AI 腔嚴重、角色 OOC）。為了解決這個痛點，我們將創作流程嚴格劃分為三大 Phase。透過結構化的中繼文檔（JSON 與 Markdown），強迫 AI 遵循我們定義的「小說編排 8 步流程」，並加上獨家的聲學標記轉換（ASMR 格式），徹底重塑 AI 輔助創作的工作流。

## 詳細內容

### 三階段生命週期 (Three Phases Lifecycle)

本 Skill 透過三個明確的階段，保障小說創作的邏輯性與連貫性。

#### 🟢 Phase A：故事規劃（新項目啟動）
這是一個強制性的「互動式 Q&A」環節。系統必須**嚴格執行一問一答**，直到用戶回答完 7 大關鍵問題後，方可產出 `故事設定.md` 與 `人物卡.md`。
1. **關鍵提問**：拋出 7 大核心問題，等待全部收斂。
2. **創作定位與大綱**：確立受眾定位、核心主題及一句話大綱（Logline）。
3. **世界觀設計**：梳理世界概要、社會階級結構與視覺美學風格。
4. **人物卡**：建立標準化角色列表（包含內在動機、外在缺陷、特有語氣）。
5. **劇情與章節規劃**：佈局三幕結構、主線成長弧度、關鍵高潮場景。
6. **場景策略**：制定情感梯度、情節推動的快慢節奏與五感描寫標籤。
7. **章節鉤子**：設計每一章的章首帶入句型、章尾懸念（Cliffhanger）。

#### 🔵 Phase B：章節 Prompt 生成
根據 Phase A 確立的設定檔，AI 會自動為後續的《每一章》生成獨立的指令卡檔：`chXX_prompt.json`。
這確保了在長篇連載中，每一章的生成都有自己的邊界，不會因為上下文過長而導致幻覺。

#### 🔴 Phase C：正文創作（8 步編排流程）
當準備進入真實的文字產出時，系統將嚴格執行以下 8 個步驟：

| 步驟 | 核心任務 | 細節說明 |
| :---: | :--- | :--- |
| **1** | **讀取指令卡** | 解析 `chXX_prompt.json` 取得該章節的目標與限制。 |
| **2** | **建立場景骨架** | 搭建「開場 → 衝突發生 → 階段落點」的三幕微結構。 |
| **3** | **角色語氣校準** | 根據 `人物卡.md` 修正對白，避免千人一面。 |
| **4** | **五感場景填充** | **【整合 RAG 系統】** 呼叫外部檢索庫，獲取同類場景參考文本輔助描寫視、聽、觸、嗅、味。 |
| **5** | **情感曲線調控** | 審視段落內的「張力拉高」與「情緒釋放」節奏。 |
| **6** | **對話自然化** | 徹底執行去除 AI 說教感：加入語氣助詞、對白省略及打斷。 |
| **7** | **輸出正文版** | 產出符合傳統網文排版、第三人稱的章節檔案。 |
| **8** | **轉換 ASMR 版** | 第二人稱化、加入 `[...]` 停頓記號與呼吸音標記。 |

### 整合 RAG 檢索系統（五感填充聯動）
在執行 Phase C 的 **Step 4** 時，程式會主動提取 `chXX_prompt.json` 裡的場景標籤（例如：`[賽博朋克, 霓虹雨夜, 追逐]`），傳送給 07.7 標準下搭建的「三層混合 RAG 系統」。
傳回的真實人類網文範例將作為「靈感提示」展示給用戶，用戶可指示 AI 吸收該段落的寫作技法，而非生硬抄襲，從而極大提升情境的真實感。

## 實戰範例

### Skill 觸發邏輯（自動分流）
開發者不需手動指定目前進度，系統入口腳本會依據當前工作目錄的檔案狀態自動分流：

```python
def determine_phase(directory):
    has_setting = exists("故事設定.md") and exists("人物卡.md")
    has_prompt = check_regex_exists(r"ch\d+_prompt\.json")
    
    if has_setting and has_prompt:
        # 已有設定與目前章節指令，直接開始寫作
        return Router.goto(PHASE_C)
    elif has_setting and not has_prompt:
        # 只有大綱，需要先生成章節指令
        return Router.goto(PHASE_B, trigger_next=PHASE_C)
    else:
        # 什麼都沒有，從頭開始問答
        return Router.goto(PHASE_A, trigger_next=PHASE_B)
```

### ASMR 版腳本格式範例
系統在匯出有聲書版本時，會自動改變人稱並埋入音聲提示：
> *(雨水擊打鐵皮聲，音量漸弱)*
> 你靠在冰冷的牆上，劇烈地喘息著。 `[...兩秒停頓...]`
> 「別過來...」你咬著下唇，聲音有些發顫。
> *(腳步聲逼近，皮鞋踩水聲)*

## 注意事項

⚠️ **去 AI 化（品質防線）**
請嚴格遵守 `banned_expressions.md` 禁用清單。絕對禁止出現諸如「然而」、「這不僅是一場...更是一次...」、「總而言之」、「宛如命運的交響曲」等常見的大模型八股文腔調。

💡 **ASMR 轉換要點**
ASMR 版腳本並非單純把「他」替換成「你」。必須拉近空間感，並增加「聽覺」與「微小觸覺」在行文中的比例。所有的聲音提示詞，請對照引用 `sound_cues.md` 中的標準代碼，以便後續直接餵給 TTS（文字轉語音）引擎進行自動混音。
