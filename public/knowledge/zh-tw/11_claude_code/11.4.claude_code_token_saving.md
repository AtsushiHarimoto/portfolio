# 11.4 Claude Code Token 節省策略全攻略

> **類型**: 最佳實踐 + 工具配置
> **日期**: 2026-03-27
> **來源**: Claude Code 實戰工具鏈配置經驗

---

## 摘要

在 AI 驅動的自動化編程環境中，Token 不僅代表你的 API 成本，更直接決定了模型的推理速度與上下文記憶能力。本文將深入探討我們在 Claude Code 開發環境中所實作的一套完整 Token 節省工具鏈。透過攔截並壓縮終端機輸出（RTK、tokf）、原生檔案讀取限制（permissions.deny）、優化工具呼叫方式（PTC），以及動態切換 AI 模型的路由策略，我們能將不必要的 Context 消耗大幅降低 60% 以上，為複雜的推理任務保留充足的記憶力與算力。 

> [!NOTE]
> 💡 **白話文解釋**：想像 Token 是你出國旅行的「行李限重」。如果你把整座房子（完整的 npm install 日誌、十萬行的 lock 檔）都塞進行李箱，不僅超重罰款（API 超支），到了當地還很難找到你要的衣服（模型失憶）。我們的節省策略就是一套自動化的「行李真空壓縮袋」。

---

## 背景

隨著開發者日益依賴 Claude Code 等 Agentic 開發工具，一個經常被忽視的隱形殺手開始浮現：**「冗餘日誌造成的 Context 溢出」**。

當 Claude 在背景執行日常的開發指令時（例如 `npm install`、`cargo build`、`git diff` 或是各種測試指令），往往會伴隨數百至數千行的終端機輸出。這些輸出對於人類開發者來說或許可以一掃而過，但在 AI 的視角下，每一個字元都會被精確地計入 Context Window 之中。

這種情況會帶來三個嚴重的問題：
1. **龐大的 API 開銷**：毫無價值的依賴套件安裝日誌被反覆送到模型中進行運算。
2. **回應延遲飆升**：隨著 Context 越來越大，每次與模型的交互延遲（TTFT）都會顯著增加。
3. **注意力偏移（Attention Dilution）**：當幾萬個 Token 都被繁雜的系統預設輸出佔滿時，模型對於核心業務邏輯的注意力會大幅下降，甚至會出現「忘記」前幾個步驟指令的狀況。

為了解決這些問題，我們沒有選擇單純地要求 AI「少印點東西」，而是從系統架構層面切入，實施了一套全方位的 Token 節省策略。

---

## 核心策略

### 1. RTK：Bash 輸出壓縮 (Rust Token Killer)

RTK 是我們這套工具鏈的先鋒，主要針對最容易產生「廢話」的系統級指令操作。它利用 Claude Code 的 `PreToolUse` hook 機制，在 Bash 工具將輸出回傳給 AI 之前，進行了一層智慧攔截與壓縮。

- **運作機制**：RTK 專門針對 `git`、`npm`、`cargo`、`docker` 等高頻且囉嗦的指令進行壓縮。把動輒數百行的無用日誌收斂為精簡的狀態報告。
- **智慧容錯配置 (`mode = "failures"`)**：這是 RTK 最核心的殺手級功能。在 `[tee]` section 設置此模式後，系統會自動判斷指令的 exit code。**如果測試成功或編譯通過**，RTK 會極限壓縮輸出，因為 AI 不需要知道成功背後的細節；但**如果測試失敗**，RTK 就會保留完整的 Error stack trace，讓模型有足夠的上下文進行 Debug。
- **配置路徑**：Hook 腳本通常安裝在 `~/.claude/hooks/rtk-rewrite.sh`。
- **節省效益**：在常規的開發循環中，這項策略可減少這類指令約 60% 至 90% 的 Context 佔用。

### 2. tokf：補充過濾層 (Token Filter)

儘管 RTK 表現優異，但仍有一些邊緣指令或是非標準框架的日誌難以被完全捕捉。因此我們引入了 `tokf` 作為補充層次。

- **功能互補**：tokf 同樣利用 `PreToolUse` hook 來攔截 Bash 輸出，主要作為泛用型的正則表達式與模式匹配過濾器，將那些不被 RTK 覆蓋到的殘餘冗長日誌去除。
- **依賴要求**：以 Rust 開發，具備極高的執行效率，不會拖慢指令的執行時間。環境需要 Rust 1.93+ 以上的支援。

### 3. permissions.deny：讀檔攔截

有時候系統最大的 Token 漏洞不是來自指令輸出，而是 AI「誤讀」了巨大的檔案。例如，當 Claude 為了了解套件版本，無意間讀取了整個 `package-lock.json` 時，幾萬個 token 瞬間就蒸發了。

- **原生防線**：利用 Claude Code 原生的 `.claude/settings.json` 檔案配置 `deny` 陣列。
- **典型阻擋清單**：
  ```json
  "permissions": {
    "deny": [
      "node_modules/**",
      "**/*.lock",
      "dist/**",
      ".next/**",
      "**/*.log"
    ]
  }
  ```
- **顯著效益**：每個 lock 檔（如 `pnpm-lock.yaml` 等）的攔截，通常能為單次對話省下 30k 到 80k 不等的 token 消耗。這同時能迫使 AI 去讀取更精簡的 `package.json` 或 `Cargo.toml`。

### 4. PTC 原則：批量讀檔 (Programmatic Tool Calling)

這是一種改變模型預設行為的提示詞（Prompt）與行為策略原則。

- **痛點**：AI 預設傾向於使用內建的 `Read` 工具來探索程式碼。但如果它需要檢視散落在 5 個檔案中的特定函數，它可能會連續呼叫 5 次 `Read` 工具，這將引入大量不需要的上下文（整個檔案的內容），且多次 Tool call 的來回會大幅拉長執行時間。
- **策略轉換**：我們在規範中強制要求 AI 優先採用 Bash 工具結合指令來檢索程式碼。例如，使用 `grep -n "TODO" src/` 或 `awk` 腳本，一次性獲取這些檔案中的特定片段。
- **效益**：從「被動接收全量文件」轉變為「主動檢索精確片段」，不僅大幅減少 token 使用量，也顯著提升了獲取特定資訊的速度。

### 5. AI 模型分配路由

殺雞焉用牛刀？這是降低 API 成本與提高效率的終極策略。並非所有的任務都需要地表最強的推理模型。我們設計了三層架構的模型路由機制：

1. **Opus 層級**：為架構設計、複雜演算法創作、深層 Bug 除錯保留。
2. **Sonnet 層級**：負責主要的 Coding、代碼重構與分析工作（性價比之王）。
3. **Antigravity / Gemini 層級**：負責常規的 UI 組件堆疊、日常 Routine 腳本、簡單文件編寫。

為確保模型路由順利運作，我們在任務執行前，要求 AI 優先輸出一段評估日誌，格式如下：
`複雜度：[High/Medium/Low]｜當前：[Model]｜[✓ 匹配 / ⚠ 建議換]`
透過這個快檢機制，開發者可以在任務前期就決定是否要手動切換模型，避免不必要的資源浪費。

## 三層配置架構

為了讓這套 Token 節省策略既強大又不干擾一般的開發流程，我們採用了「職責分離（Separation of Concerns）」的三層配置架構：

| 配置層級 | 檔案路徑 | 核心職責與設計哲學 |
|---------|---------|-----------------|
| **行為指令層** | `~/.claude/CLAUDE.md` | 用來定義 AI 的行為原則，包含 AI 模型分配路由、任務前複雜度快檢格式，以及要求優先使用 PTC 原則進行文件讀取。這層直接影響 AI 每一步的決策。 |
| **系統設定層** | `.claude/settings.json` | 處理基層的防護機制。包含 `permissions.deny` 以及所有的 Hook 設定檔。這層是靜態且強制執行的規則。 |
| **按需載入層** | `.claude/rules/token-tools-setup.md`| 提供詳細的工具安裝與配置指引。**設計亮點**：這份文件平時並不會被載入 Context。只有當需要在新專案初始化環境時，才要求 AI 讀取，實質上做到「不佔用無謂的 Context」。 |

## 實戰效果

導入這套全面的 Token 節省策略後，我們在長期的開發專案中觀察到了顯著的效能突破與成本下降。以下為典型的節省數據預估參考：

| 工具與策略 | 攔截對象 | 典型節省指標 |
|----------|---------|------------|
| **RTK** | Bash 工具輸出（`git`/`npm`/`cargo`/`docker` 等） | 減少 60%–90% 的指令廢話輸出 |
| **tokf** | Bash 輸出（補充 RTK 未涵蓋之長尾與邊緣工具） | 提供額外 60%–90% 的特定過濾縮減 |
| **permissions.deny** | 大型生成檔案與套件相依清單讀取阻擋 | 避免每一次誤讀，單檔省下 30k–80k tokens |
| **PTC 原則** | 多次全量 Read 轉向 Bash `grep`/`awk` 單次檢索 | 針對特定查詢情境可省下近 60% 的文件閱讀開銷 |
| **模型路由** | 將前端 UI 或日常 Routine 任務下放給 Gemini/Antigravity | 大幅降低 API 費用，並替 Opus 保留充足速率限制額度 |

## 快速安裝

想在自己的 Claude Code 環境中部署這套工具鏈，可以依照以下步驟進行：

### 1. 安裝 RTK 並配置 Hook
開啟終端機，確保你有安裝 Cargo，然後執行：
```bash
# 全局安裝 RTK
cargo install --git https://github.com/rtk-ai/rtk

# 初始化設定並自動啟動 patch 機制
rtk init -g --auto-patch
```
*這將自動在 `~/.claude/hooks/rtk-rewrite.sh` 建立對應的 hook。請重啟 Claude Code 使其生效。*

### 2. 安裝 tokf (需 Rust 1.93+)
```bash
# 安裝 tokf
cargo install tokf

# 註冊為 Global 的 hook
tokf hook install --global
```

### 3. 配置 permissions.deny 防護網
在專案根目錄或是全域 `.claude/settings.json` 中加入以下設定：
```json
{
  "permissions": {
    "deny": [
      "node_modules/**",
      "**/*.lock",
      "dist/**",
      "build/**",
      ".next/**",
      "**/*.log"
    ]
  }
}
```
