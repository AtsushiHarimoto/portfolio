## Abstract

In AI-driven automated programming environments, Tokens not only represent your API costs but also directly determine the model's inference speed and context memory capabilities. This article delves into a complete token-saving toolchain we implemented in our C​laude Code development environment. By intercepting and compressing terminal outputs (RTK, tokf), limiting native file reading (`permissions.deny`), optimizing tool call methods (PTC), and employing a dynamic AI model routing strategy, we can reduce unnecessary Context consumption by over 60%. This preserves sufficient memory and compute power for complex reasoning tasks.

> [!NOTE]
> 💡 **In Plain English**: Imagine Tokens as your "luggage weight limit" when traveling abroad. If you stuff your entire house (e.g., complete `npm install` logs, 100,000-line lock files) into your suitcase, not only will you pay overweight fines (API overspending), but it will also be hard to find the clothes you need when you arrive (model amnesia). Our saving strategy acts as an automated "vacuum storage bag for your luggage."

## Background

As developers increasingly rely on Agentic development tools like C​laude Code, an often-overlooked silent killer begins to emerge: **"Context overflow caused by redundant logs."**

When Claude runs everyday development commands in the background (such as `npm install`, `cargo build`, `git diff`, or various test commands), it is often accompanied by hundreds to thousands of lines of terminal output. These outputs might be something human developers can just glance over, but from an AI's perspective, every single character is strictly counted towards the Context Window.

This situation leads to three severe problems:
1. **Massive API Costs**: Worthless dependency installation logs are repeatedly sent to the model for computation.
2. **Soaring Response Latency**: As the Context grows larger, the Time to First Token (TTFT) in each interaction with the model significantly increases.
3. **Attention Dilution**: When tens of thousands of tokens are occupied by cluttered default system outputs, the model's attention to the core business logic drops drastically, even leading to scenarios where it "forgets" instructions from previous steps.

## Core Strategies

### 1. RTK: Bash Output Compression (Rust Token Killer)

RTK leverages C​laude Code's `PreToolUse` hook mechanism to intelligently intercept and compress the output of Bash tools before they are returned to the AI.

- **Mechanism**: Compresses high-frequency commands such as `git`, `npm`, `cargo`, and `docker`.
- **Smart Fault-Tolerance Configuration**: Sets `mode = "failures"` in the `[tee]` section — retains complete output when a test fails, applies extreme compression when successful.
- **Savings Impact**: Eliminates 60–90% of nonsense command output.

### 2. tokf: Supplementary Filtering Layer

Also utilizing the `PreToolUse` hook, this acts as a supplementary layer to RTK, covering residual verbose logs from non-standard frameworks. Requires Rust 1.93+.

### 3. permissions.deny: File Reading Interception

Configure the deny array in `.claude/settings.json` to prevent Claude from misreading massive auto-generated files:

```json
{
  "permissions": {
    "deny": ["node_modules/**", "**/*.lock", "dist/**", ".next/**", "**/*.log"]
  }
}
```

Intercepting each lock file can save 30k–80k tokens.

### 4. PTC Principle: Batch File Reading

Prioritize using Bash `grep`/`awk` to extract specific snippets from multiple files in a single pass, rather than calling the Read tool multiple times to read entire files.

### 5. AI Model Routing Allocation

Three-tier architecture: **Opus** (complex reasoning) → **Sonnet** (primary coding) → **Antigravity/Gemini** (UI/Routine tasks). A pre-task output complexity assessment tag ensures the most appropriate model is used.

## Three-Tier Configuration Architecture

| Configuration Level | File Path | Core Responsibility |
|---------|---------|---------|
| **Behavioral Instruction Layer** | `~/.claude/CLAUDE.md` | AI routing rules, pre-task quick-check formatting, PTC principle |
| **System Settings Layer** | `.claude/settings.json` | `permissions.deny` + Hook settings |
| **On-Demand Loading Layer** | `.claude/rules/token-tools-setup.md` | Installation guides (Context not loaded normally) |

## Quick Installation

```bash
# RTK
cargo install --git https://github.com/rtk-ai/rtk
rtk init -g --auto-patch  # Takes effect after restarting Claude Code

# tokf (Requires Rust 1.93+)
cargo install tokf
tokf hook install --global
```
