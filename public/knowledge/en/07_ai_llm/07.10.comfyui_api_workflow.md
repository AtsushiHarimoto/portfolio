## 摘要

ComfyUI 以其基於節點（Node-based）的圖形化介面在 AI 藝術家圈子中聲名大噪，然而其真正的底層實力在於其卓越的「無頭模式」（Headless Mode）與強大的 REST API 架構。對於資深開發者而言，GUI 僅僅是開發與除錯的場景模擬器，而 API 才是將生成式 AI 整合進企業級產品線、實現大規模批量生產的核心路徑。透過 API，我們可以將複雜的影像生成邏輯解構，讓每一次生成都成為可編程、可重複且可監視的自動化任務。

本篇文章將深入探討如何將手動開發的 ComfyUI Workflow 轉化為高效運作的自動化生產線。我們將從基礎的 WebSocket 通訊架構出發，進階到動態參數解析、LoRA Batch 評估，以及針對 GPU 運算資源的佇列調優與 OOM（記憶體溢出）防禦策略。這不僅僅是技術的遷移，更是從「單點創作」到「工業化生產」的思維演進。

> [!NOTE]
> 💡 **白話文解釋**：
> 想像你在 Photoshop 裡修一張圖，需要手動點選濾鏡、調整係數。如果你今天要修 1 萬張圖怎麼辦？你可能會錄製「動作（Action）」。但如果這 1 萬張圖每一張的濾鏡參數都要根據圖片內容自動計算，動作就失靈了。這時候，ComfyUI API 就像是讓你直接用 Python「寫」出一套自動修圖系統，它不再是一個軟體介面，而是一個聽命於程式碼的「雲端算力工廠」。你下指令，它開工，你睡覺，它產圖。

## 背景

在傳統的 GUI 操作模式下，使用者面臨著幾個明顯的生產力瓶頸：
1.  **無法批量化**：若需測試 50 個不同的 LoRA 權重或 100 種不同的 Prompt 組合，手動修改節點參數與點擊「Queue Prompt」將會耗費數小時的重複性勞動。
2.  **無法跨系統整合**：當我們希望在 Web 網站或 App 中集成 AI 生成功能時，不可能要求後台有一個人一直在那點滑鼠。
3.  **監控缺失**：GUI 難以提供精確的耗時統計、顯存利用率監控以及自動化的錯誤重試機制，這對於追求穩定性的工程環境是不可接受的。

## 詳細內容

### 1. ComfyUI API 架構概覽

ComfyUI 本質上是一個基於 Python 的伺服器，啟動時會建立一個後端服務（預設為 `127.0.0.1:8188`）。它的通訊機制分為兩大支柱：

*   **REST API 端點**：
    *   `/prompt` (POST)：這是最重要的端點，用於提交你的 Workflow JSON 到伺服器佇列。
    *   `/history` (GET)：查詢已完成任務的狀態與輸出結果（例如圖片路徑）。
    *   `/upload/image` (POST)：上傳圖片（常用於 ControlNet 參考圖或 Image-to-Image）。
    *   `/queue` (GET/POST)：查看當前排隊狀況或清空佇列。

*   **WebSocket 端點**：
    *   `/ws?clientId={id}`：用於建立長連接。伺服器會透過這個管道實時推播「目前執行到哪一個節點」、「生成進度百分比」以及「執行錯誤訊息」。

當我們提交一個 JSON 時，ComfyUI 會將其視為一個「有向無環圖」（DAG）。伺服器會遍歷節點，檢查依賴關係，並緩存已執行的節點以最佳化速度。

### 2. 匯出 workflow API JSON

這是初學者最容易踩的坑。**普通的 `.json` 儲存檔無法直接用於 API 調用。**

*   **普通 Workflow JSON**：包含節點的座標、連線顏色、UI 配置等資訊。
*   **API 格式 JSON**：僅包含執行邏輯、參數值與節點 ID。

**操作步驟**：
1.  開啟 ComfyUI 設定（右側齒輪圖示）。
2.  勾選 **"Enable Dev mode Options"**。
3.  此時右側面板會出現 **"Save (API Format)"** 按鈕。
4.  點擊匯出，這份 JSON 才是我們程式端要操作的對象。

**差異點**：在 API JSON 中，每個節點都有一個唯一的 `class_type`（如 `CheckpointLoaderSimple`）和 `inputs`。我們需要關注的是節點 ID（Node ID，通常是字串形式的數字，如 `"6"`），這將是我們在 Python 中定位並修改參數的唯一指標。

### 3. Python 客戶端實作

以下是一個精簡但完整的 Python 實作範例。它使用了 `requests` 處理 HTTP 請求，並使用 `websockets` 監聽進度。

```python
import websocket # pip install websocket-client
import requests
import json
import uuid
import urllib.parse
import os

server_address = "127.0.0.1:8188"
client_id = str(uuid.uuid4())

def queue_prompt(prompt):
    p = {"prompt": prompt, "client_id": client_id}
    data = json.dumps(p).encode('utf-8')
    res = requests.post(f"http://{server_address}/prompt", data=data)
    return res.json()

def get_image(filename, subfolder, folder_type):
    data = {"filename": filename, "subfolder": subfolder, "type": folder_type}
    url_values = urllib.parse.urlencode(data)
    res = requests.get(f"http://{server_address}/view?{url_values}")
    return res.content

def run_workflow(prompt_workflow):
    ws = websocket.WebSocket()
    ws.connect(f"ws://{server_address}/ws?clientId={client_id}")
    
    prompt_res = queue_prompt(prompt_workflow)
    prompt_id = prompt_res['prompt_id']
    print(f"任務已提交，ID: {prompt_id}")

    output_images = {}
    
    while True:
        out = ws.recv()
        if isinstance(out, str):
            message = json.loads(out)
            if message['type'] == 'executing':
                data = message['data']
                if data['node'] is None and data['prompt_id'] == prompt_id:
                    break # 執行完畢
                else:
                    print(f"正在執行節點: {data['node']}")
            elif message['type'] == 'progress':
                data = message['data']
                print(f"進度: {data['value']}/{data['max']}")
        else:
            continue # 忽略二進制數據

    # 查詢歷史紀錄獲取輸出文件路徑
    history_res = requests.get(f"http://{server_address}/history/{prompt_id}").json()
    history = history_res[prompt_id]
    
    for node_id in history['outputs']:
        node_output = history['outputs'][node_id]
        if 'images' in node_output:
            for image in node_output['images']:
                image_data = get_image(image['filename'], image['subfolder'], image['type'])
                output_images[image['filename']] = image_data
                
    ws.close()
    return output_images

# 使用範例
with open("my_workflow_api.json", "r", encoding="utf-8") as f:
    workflow_data = json.load(f)

# 修改 prompt
workflow_data["6"]["inputs"]["text"] = "A majestic dragon sitting on a skyscraper, cyberpunk style, neon lights"
# 修改 seed
workflow_data["3"]["inputs"]["seed"] = 42

images = run_workflow(workflow_data)
for name, content in images.items():
    with open(name, "wb") as f:
        f.write(content)
```

### 4. 動態修改 workflow 參數

在自動化場景中，硬編碼 Node ID 是不可取的。建議在開發 Workflow 時，為節點分配 **Title**，但在 API JSON 中，Title 並不會作為 Key 出現。

**最佳實踐建議**：
建立一個 Mapping 函式，在加載 JSON 後遍歷所有節點，根據 `_meta` 標籤（如果有）或特定的 `inputs` 內容來定位。

**批量生成策略（Grid Search）**：
我們可以輕鬆實現「參數矩陣」。例如，測試 `CFG Scale` 從 1.0 到 10.0，間隔 0.5：
```python
for cfg in [x * 0.5 for x in range(2, 21)]:
    workflow_data["3"]["inputs"]["cfg"] = cfg
    # 執行任務並儲存圖片名為 f"result_cfg_{cfg}.png"
```

### 5. 與 LoRA 整合

LoRA 的動態切換是 API 調用的高頻需求。通常推薦使用 `LoraStack` 類型的節點（來自自定義擴展如 `Efficiency Nodes`），這允許我們透過傳遞一個清單（List）來一次性加載多個 LoRA。

在程式化處理時：
*   **動態切換模型**：修改 `CheckpointLoaderSimple` 節點的 `ckpt_name`。
*   **遍歷 LoRA 版本**：如果你有一批訓練中的 LoRA 存檔，可以寫一個循環讀取資料夾下的模型名稱，動態注入到 Workflow 中，實現自動化的「過門測試」（Gate Test）。

### 6. 佇列管理與錯誤處理

在伺服器端運行時，穩定性大於一切。

*   **併發限制**：ComfyUI 預設一次只執行一個任務。如果你有多張顯卡，需要啟動多個伺服器實例並透過 Load Balancer 分發任務。
*   **OOM 重試機制**：
    ```python
    try:
        run_workflow(wf)
    except Exception as e:
        if "CUDA out of memory" in str(e):
            print("顯存爆了！嘗試調小解析度或排空佇列重試...")
            # 這裡可以寫降低長寬的邏輯
    ```
*   **中斷恢復**：利用 `client_id`。如果 Python 客戶端中斷連接，伺服器上的任務會繼續運行。重新連接並查詢 `/history` 即可找回任務。

## 效能調優

1.  **並發限制建議**：對於單張 RTX 4090，建議佇列長度不要超過 50，以避免 WebSocket 連接過久導致超時。
2.  **圖片儲存策略**：ComfyUI 預設儲存在 `output` 資料夾。在 API 模式下，建議將產出的圖片二進制流直接轉存至雲端物件儲存（如 AWS S3），並定期清理伺服器磁碟。
3.  **磁碟空間管理**：`temp` 資料夾會積累大量的預覽圖，建議在啟動腳本中加入 `--temp-directory` 設定或定期定時清理 cron job。

## 常見問題

| 問題 | 可能原因 | 處理方式 |
| :--- | :--- | :--- |
| **WebSocket 斷線** | 任務執行時間過長或網絡震盪。 | 實作 `while True` 包裹的心跳機制與斷線自動重連。 |
| **JSON 格式錯誤** | 誤用了 GUI 儲存的 JSON，而非 API Format。 | 確認開發模式已開啟，使用開發者選項導出的 JSON。 |
| **CUDA OOM** | 同時加載了多個大型 Checkpoint 或 Flux 等重型模型。 | 在程式端確保前一個任務結束（Executed）後才提交下一個任務；或者手動調用 `/free` 清理內存。 |
| **輸出圖片找不到** | 節點 ID 改動或使用某些不支持 API 輸出的自定義節點。 | 檢查 `/history` 傳回的 JSON 結構，確認輸出的節點 ID 是否正確。 |
