## 摘要

在當今的 AI 協作開發時代，多數開發者仍把 AI 助手當作單純的指令接收器，缺乏與現有專案開發流程的深度整合與卡控。而 C​laude Code Hooks 的出現，革命性地改變了我們與大型語言模型互動的方式。它允許我們在 AI 執行特定工具或動作的前後，自動觸發自定義的檢查腳本，進而在修改檔案、網路請求或流程停止時主動介入。這不僅大幅降低了人為疏忽所帶來的風險，更是將 AI 代碼產出品質與企業內部規範完美接軌的核心樞紐。

透過強大又靈活的 Hooks 系統，我們可以將繁瑣的程式碼審查、後置的格式化作業以及嚴謹的安全管制機制，無縫且自動地嵌入 C​laude Code 的工作流中。無論是硬性阻擋不合規的危險 Git 操作，還是在寫入模型層檔案前強制執行 Lint，Hooks 都能確保 AI 產出的每一行邏輯都符合開發團隊的最高標準。這也代表系統工程師可以放心地將更大程度的自主性交予 AI，真正體驗到零摩擦的「自動化防呆」協作模式。

> [!NOTE]
> 💡 **白話文解釋**：想像一下，C​laude Code 是你剛聘僱的超級天才實習生，他寫扣超快，但偶爾會犯傻忘記公司的程式碼規矩。Hooks 就像是你在他辦公桌旁安裝的「自動安檢門」與「貼心小秘書」。只要這名實習生想執行「發送推播 (PostToolUse)」前，安檢門就會「嗶嗶嗶」自動檢查有沒有夾帶機密資料；或者在他準備「打卡下班回家 (Stop)」時，小秘書會自動跳出來提醒他：「哎！別急著走，記得先寫完今天的工作日誌啊！」

## 背景

在過去沒有 Hooks 加持的日子裡，信任 AI 自主執行本地指令是一種「走鋼索」的刺激體驗。開發團隊時常會遇到這類痛點：AI 俐落地幫你重構完幾百行邏輯，卻忘記順手跑一下 `eslint` 或 `prettier`，導致送出 PR 時 CI/CD 的紅燈亮個不停；又或者 AI 為了幫你解決衝突，自作主張執行了強制覆蓋的 Git 指令，引發一場災難。最令維運團隊頭痛的是，一旦賦予 AI 過大的作業系統權限，它極有可能無意間改動到核心的環境變數或資料庫設定檔。

如果你總是得事後諸葛地上演「尋 Bug 記」，或是花大量時間收拾殘局，AI 帶來的效率提升將被大幅抵銷。為了解決這些擦屁股的隱形成本，我們迫切需要建立一道護城河：**在 AI 執行高風險、高重複性動作的關鍵路徑上，預先埋設檢驗點與攔截網**。這正是事件觸發自動化（Event-driven Automation）的精髓所在，也是 Claude Code 引入 Hooks 機制最大的使命——讓規矩跑在破壞之前，防患於未然。

## 詳細內容

### 1. Hooks 系統架構

C​laude Code 的 Hooks 系統主要是圍繞著 AI 的「動作生命週期」來設計。要寫出好的自動化流程，首先得熟悉以下四種事件類型，它們是你掌握全域控制權的基礎：

| 事件類型 (Event) | 觸發時機 | 典型應用場景 |
| :--- | :--- | :--- |
| `PreToolUse` | AI 決定調用某個內部工具（例如讀寫檔案、執行 Bash）**之前**觸發。 | 攔截危險操作指令、拒絕覆蓋特定核心檔案、執行前置的權限動態檢查。 |
| `PostToolUse` | AI 執行完工具並取得回傳值**之後**，將結果傳遞給模型思考之前觸發。 | 自動格式化剛被修改的檔案、檢查是否產生編譯錯誤並將提醒塞回給 AI 讓它自我修正。 |
| `Stop` | 當目前的 C​laude Code Session 結束，或是 AI 判定任務完成宣告停止時觸發。 | 將本次的修改代碼總結輸出、自動執行 Git 推送或備份、清理過程中產生的暫存垃圾檔。 |
| `Notification` | 當整合系統發生特定的非同步狀態改變，或接收到重要背景通知時觸發。 | 監控系統底層的變化、觸發第三方通訊軟體（如 Slack、Teams）的自動化部署訊息推播。 |

### 2. settings.json 配置結構

要在你的專案專屬環境中啟用這套自動化護身符，需要在 `.claude-code/` 資料夾（或全域設定）中配置 `settings.json`。以下提供一份真實可以直接套用於生產環境的 JSON 配置範本，涵蓋了事前檢查、事後格式化與結束摘要的三重防護：

```json
{
  "version": "1.0",
  "hooks": {
    "preToolUse": [
      {
        "name": "Strict Security Assessment",
        "tools": ["Bash", "WriteFile"],
        "script": "./.hooks/security_check.sh",
        "description": "攔截 AI 對機密設定檔的任何改動或高風險指令。"
      }
    ],
    "postToolUse": [
      {
        "name": "Pre-commit Auto Format",
        "tools": ["WriteFile", "EditFile"],
        "script": "./.hooks/auto_format.sh",
        "description": "在檔案被寫入後自動執行，確保程式碼風格無暇。"
      }
    ],
    "stop": [
      {
        "name": "Session Git Summary",
        "script": "./.hooks/show_summary.sh",
        "description": "每次離開對話前自動計算並總結本次的所有代碼變動量。"
      }
    ]
  }
}
```

### 3. 實用 Hook 配方

這裡整理了三個實際應用程式開發時，CP 值極高的 Bash 腳本配方。你可以直接將這些配方複製到對應的 `.sh` 檔案中，作為團隊規範的基石：

**配方一：防止核彈爆炸的 Git 操作保護（PreToolUse）**
AI 有時候為了省事會給出過激的命令，這個腳本能保住代碼庫跟你自己的飯碗。
```bash
#!/bin/bash
# 檔案位置：.hooks/security_check.sh

# 從 stdin 讀取 C​laude 轉換來的 JSON 工具參數
TOOL_INPUT=$(cat /dev/stdin)
COMMAND=$(echo "$TOOL_INPUT" | jq -r '.command // empty')

# 只要檢測到帶有強制推送的關鍵字，馬上亮紅燈
if [[ "$COMMAND" == *"git push"* && "$COMMAND" == *"-f"* ]]; then
  echo "❌ 警告 [Hook 攔截]: 絕對禁止 AI 執行 git push -f！這非常危險，操作已阻擋。"
  exit 1 # 這裡是最關鍵的！回傳非零值強制終止 AI 接下來的工具執行
fi

echo "✅ 指令安全掃描通過。"
exit 0
```

**配方二：Python / TypeScript 自動排版精靈（PostToolUse）**
不需要一而再、再而三地跟模型強調「請幫我排版」，AI 改完檔案，我們用腳本瞬間搞定。
```bash
#!/bin/bash
# 檔案位置：.hooks/auto_format.sh

TOOL_INPUT=$(cat /dev/stdin)
FILE_PATH=$(echo "$TOOL_INPUT" | jq -r '.path // empty')

if [[ "$FILE_PATH" == *.py ]]; then
  echo "🔍 檢測到 Python 檔案變更，背景執行 Black 自動排版..."
  black "$FILE_PATH" > /dev/null 2>&1
  # 透過 Stdout 告訴 AI 剛剛系統幫忙加了哪些戲，讓它不要不知所措
  echo "✅ 系統已經在背後幫你對 $FILE_PATH 執行了 Black 格式化。"
fi
exit 0
```

**配方三：情境知識 (Context) 強制警告（PreToolUse）**
當 AI 觸碰到專案的核心地帶（如基礎設施配置區），先發送警告。
```bash
#!/bin/bash
# 檔案位置：.hooks/context_warning.sh

TOOL_INPUT=$(cat /dev/stdin)
FILE_PATH=$(echo "$TOOL_INPUT" | jq -r '.path // empty')

if [[ "$FILE_PATH" == *"terraform.tfstate"* || "$FILE_PATH" == *"config/production.json"* ]]; then
   echo "⚠️ WARNING: 你正試圖修改核心系統區塊（$FILE_PATH）。請確認你已參照最新的內部架構維護手冊！"
   # 不一定要用 exit 1 阻擋，但可以透過警告詞改變語言模型下一步的行為模式
   # AI 看到這串文字通常會變得更為謹慎
fi
exit 0
```

### 4. Hook 腳本編寫技巧

想寫出無懈可擊的 Hook，必須透澈理解 C​laude Code 系統與背後腳本溝通的「潛規則」：

*   **讀取標準輸入 (Stdin) 是唯一橋樑**：當 C​laude Code 觸發外部腳本時，它不會把參數當作命列選項傳進去，而是將所有的工具呼叫上下文打包成一份完整的 JSON，直接塞給腳本的標準輸入。你必須習慣透過 `cat /dev/stdin` 承接這些資訊，並搭配 `jq` 等指令來提取 `.path` 或 `.command` 欄位。
*   **Exit Code (退出碼) 掌握生殺大權**：你在腳本最後留下的 `exit` 數字決定了流程的命運。`exit 0` 代表綠燈通行；任何 `exit NON-ZERO`（例如 `exit 1`）都代表著紅燈攔截。一旦回傳 1，C​laude 的動作就會被強制中斷，並將你的報錯顯示在它的對話框裡。
*   **把標準輸出 (Stdout) 當作傳聲筒**：不要以為腳本裡 `echo` 的字串只會顯示給你看。如果你在 `Pre/PostToolUse` 中印出了文字，這些文字會直接穿透回語言模型的上下文記憶中。這意味著你可以透過打印錯誤提示或善意提醒，間接地「引導 / 恐嚇」AI 下一步要用什麼樣的態度去修正錯誤。

## 案例研究

**真實場景一：Session 結束自動提醒備份與防呆**
在一家新創團隊中，每天都有開發者因為忙碌，C​laude 寫完扣就直接關閉視窗下班，結果第二天其他同事拉不到最新代碼。後來他們在 `settings.json` 掛載了一支強大的 `Stop` Hook。當 AI 宣告任務完成準備退出時，腳本會在背景安靜地執行 `git status -s`。倘若它探測到工作區有絲毫未提交的程式碼，會立刻在終端機彈出一行顯眼的黃色文字：「*⚠️ 等等！您還有未 Commit 的異動！別急著閃人，要不要順手把辛勞的果實推上遠端倉庫？*」這個溫馨的小巧思，讓該團隊連續三個禮拜將代碼遺失的事故率降到了 0%。

**真實場景二：Edit 操作前自動確認設計規範**
某大型電商專案的後端架構有條鐵律：所有對 `src/models/*.ts` (資料庫模型層) 的修改，都必須同步附加上資料庫的 Migration 腳本。為了讓 AI 不要忘規矩，工程師寫了一個 `PreToolUse` Hook。只要 AI 調用編輯檔案的工具且路徑落在 `src/models/`，腳本表面上放行 (`exit 0`)，但會硬性回傳一段提示注入上下文：「*強制規則檢視：系統發現你正在修改結構描述檔，請你務必在下一個步驟生成出對應的 database migration 檔案。*」神妙的是，Claude 讀取到這段「旁白警告」後，立刻在修改完 Model 時「懂事」地接著跑出生成 Migration 的工具調用。從此，不吻合的架構設計便在萌芽階段被系統自動弭平了。

## 常見誤區

即便 Hooks 再強大，初學者在配置時如果踩到下列的坑，依然會讓體驗大打折扣。以下整理了最容易犯錯的配置狀態與解決之道：

| 錯誤示範 (Pitfalls) | 帶來的災難現象 | 正確做法與解法 |
| :--- | :--- | :--- |
| **忘記賦予腳本執行權限**<br/>(未使用 `chmod +x`) | AI 呼叫工具時終端機噴出紅通通的 `Permission Denied` 錯誤，當場卡死宣告放棄。 | 確保寫好任何 `.sh` 腳本後，第一件事就是在終端機打上：`chmod +x .hooks/*.sh`。 |
| **萬年不變的 `exit 0`** | 雖然你寫得很棒、印出了警告，但 AI 把你的警告當耳邊風，照樣大刀闊斧摧毀機密設定檔。 | 如果需要實質上的**「阻擋」**危險操作，不要只會 echo，務必使用 `exit 1` 來硬派截斷任務。 |
| **預設系統有安裝好依賴** | 你的 Hook 腳本在解析 stdin 時突然 Crash 癱瘓，才發現容器或新環境根本沒裝解析器。 | 永遠在腳本第一行加上防禦性環境檢查，例如：`command -v jq >/dev/null \|\| { echo "Missing jq"; exit 1; }`。 |
| **攔截條件寫得太寬鬆** | 腳本過於敏感，AI 連執行個無害的 `ls` 或 `pwd` 確認路徑都被擋下來，變成什麼事都做不了的木頭人模式。 | 善用 `jq` 精準解析出實際要執行的字串路徑，限縮打擊範圍，只針對高危險組合（如 `rm -rf`）再下重手。 |

## 總結

C​laude Code Hooks 自動化機制的引入，正式把 AI 助手從一個單純接收口令的「被動執行者」，蛻變為一位懂得趨吉避凶、能嚴格遵守團隊紀律的「主動協作者」。它不僅補足了自動化代理在生成程式碼時容易產生失控風險的盲區，更讓繁雜的程式碼審查與邊界異常卡控，巧妙地左移到了邏輯撰寫的當下。現在就為專案配置你的第一個 Hook 吧！透過建立彈性且強韌的事件攔截網路，你將能享受到真正安全無虞、流暢且高度客製化的 AI 結對程式編輯體驗！
